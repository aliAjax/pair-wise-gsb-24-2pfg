# hxwl-10 考古探方记录

遗址探方 — 土样（袋号） — 浮选批次的一条可续作档案。

## 业务规则

- **一条续作记录**：探方 1—N 土样 N—N 浮选批次（同一袋可被两条批次认领，认领取并集）。
- **离线登记 + 回连合并**：现场断网时登记进入本地 outbox；回连后**按袋号逐件合并**——同袋号不新建、不覆盖任何一方原值、认领批次做并集。
- **双方原值**：现场地层范围与实验室浮选地层范围分开存。不一致时双方原值都保留，挂"待领队核对"；领队核对只记录"采用范围"，新实验室值到达后核对自动失效。
- **统计失效 / 封存闸门**：每个探方的统计指纹（哈希）包含其全部袋的认领批次与每条浮选结果。批次结果一变指纹即变，引用该批次的探方统计失效必须重算；有未回填检测、冲突未核对或统计未重算时，封存按钮被挡住。
- **乐观并发**：批次带 `version`，提交做 CAS。两个窗口同基底提交只放行一份，败者整体收到冲突（`ConflictError`），草稿保留并显示服务器现值供比对，可续传。
- **断点重放**：批次逐袋写入暂存区，逐袋 checkpoint；故障后只补未完成袋。批次号在登记草稿时即占用，重放凭操作幂等键取回原号——**不会重复占用批次号，也不会重复写入已完成袋**。

## 技术栈

React 19 + Vite + TypeScript，无后端：

- `src/server.ts` — 用 localStorage 模拟的跨标签页共享"服务器"：CAS 读改写、Web Locks（不可用时进程内链式锁降级）、模拟延迟、故障注入、幂等表。
- `src/sync.ts` — 纯领域逻辑：统计、失效哈希、封存闸门。
- `src/store.tsx` — 客户端：在线/离线、outbox 状态机（waiting/running/done/error/conflict）、草稿、跨标签页订阅。
- `src/components/` — 探方闸门、串联记录、现场登记/续传队列、批次草稿、双窗口并发演练、事件流。

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5110
```

## 验收脚本

```bash
node scripts/smoke.mjs   # 29 条端到端断言（需先用 esbuild 打包，见下）
npx tsc --noEmit
npm run build
```

冒烟脚本打包（Node 直接执行 TS 源的 ESM 版本）：

```bash
npx esbuild src/server.ts --bundle --platform=node --format=esm --outfile=/tmp/hxwl-server.mjs
npx esbuild src/sync.ts  --bundle --platform=node --format=esm --outfile=/tmp/hxwl-sync.mjs
node scripts/smoke.mjs
```

覆盖：双窗口 CAS 一放一拒、败者续传、逐袋故障后只补未完成袋、整条重放幂等、批次号占用幂等、袋号合并不覆盖原值、双方冲突状态、统计指纹失效、封存三道闸门。

## 手动演练路径

1. 页面右上"切到离线"→ 现场登记几袋（含已存在袋号，如 `S-1001`）→ outbox 挂 waiting。
2. "切到在线"→ 自动逐件合并；S-1001 双方原值保留，记录卡片出现"请领队核对"。
3. 浮选批次卡片"结果变化，改后提交"→ 对应探方指纹变"已失效"→ 重算前封存被挡。
4. 并发演练场：两个窗口各改不同数值，分别提交（或开两个浏览器标签页同时操作 B-001）→ 一放一拒；勾选故障注入观察断点重放。
5. outbox 失败卡片上"再注入2次故障"→ 点"只重放未完成袋"，观察进度条与批次号复用。
