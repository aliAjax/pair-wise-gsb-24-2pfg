# hxwl-10 考古探方记录

遗址探方、土样袋与浮选批次的**离线优先、可续作**接续记录。

## 业务规则与落点

| 规则 | 实现 |
| --- | --- |
| 现场离线登记，回连后按袋号逐件合并 | `domain/engine.ts` outbox 队列；`store.upsertBagStratum` 以袋号为唯一键归并 |
| 现场与实验室地层范围不一致，保留双方原值等领队核对 | `BagRecord.stratum.field/lab` 双原值并置，归一化仅用于比对，`conflicts` 挂起；`resolveConflict` 由领队了结 |
| 同一袋可被两条浮选批次认领 | `BagRecord.claimedBy[]`，只去重不拒绝 |
| 浮选结果变化 → 引用该批次的探方统计失效重算 | 结果修订版本 +1；`statsSignature` 输入签名失配，`recomputeStats` 换签 |
| 统计失效/未核对/未回填检测挡住探方封存 | `evaluateSealGate`：blockers + warnings，`sealSquare` 强校验 |
| 两窗口并发提交同一批次只放行一份 | 服务端 `draftId` 窗口锁，后来者 409；落败方保留草稿 `drafts` 与冲突提示 |
| 写入失败只重做未完成样本 | 每袋独立 `status`，op 记录 `finishedBagNos`，重放跳过已写件 |
| 重放不重复占用批次号 | 建批与发号在同一临界区一次完成；重放走同一批次记录，不再次发号；register 按袋号幂等 |

封存闸门三类拦截项：

1. 未回填检测：批次内存在非 `written` 样本（pending/failed）；
2. 该探方有待领队核对的地层原值冲突；
3. 探方统计输入签名与重算时不一致（浮选结果或样本状态有变）。

## 目录

```
src/domain/
  types.ts    领域类型（探方/土样袋/批次/队列/封存闸门）
  store.ts    纯逻辑：按袋合并、签名、重算、闸门
  api.ts      模拟服务端：发号临界区、并发锁、逐袋写入、故障注入
  engine.ts   现场端：离线队列、续作重放、409 草稿保留、localStorage 续作
scripts/
  selftest.ts 43 项业务规则自检
```

## 本地运行

```bash
npm install
npm run dev        # 端口 5110
npm run selftest   # 规则自检（离线合并/续作/并发/失效封存）
npm run build      # 类型检查 + 产物构建
```

## 界面演练路径

1. 窗口 A 切「离线」，登记与实验室口径不同的袋（如 B-1002 录「第三层」），再回连 → 台账双原值并置、标「待领队核对」；
2. 勾「模拟写入故障」提交 3 袋批次 → 前 2 件写入、第 3 件失败；点「立即续作」→ 只补第 3 件，批次号 FX-xxxx 不变；
3. 点「并发演练」→ 两窗口同编一批，只一份拿到批次号，另一份在「被挡下的草稿」中留冲突提示；
4. 实验室面板修订浮选结果 → 对应探方统计数字标红失配、封存被挡；「重算统计」后封存放行；
5. 领队面板给冲突袋下核对结论后，探方闸门解除。

现场端草稿/队列按窗口持久化在 `localStorage`，刷新后可继续续作；服务端快照不持久化，重置按钮恢复初始样例。
